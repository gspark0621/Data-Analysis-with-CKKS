## 0. 전체 흐름

```
클라이언트                          서버 (암호문만 봄)
─────────                          ──────────────────
분위수 구간화 (n_max)
subsample 비율 결정
one-hot 인코딩 + 암호화   ──────→   ① prefix 누적합      (비교 없이 회전만)
                                    ② 레벨 루프 × D
                                        T1  파티션 통계
                                        T2  분할 점수 (분자만)
                                        T3  argmax  = log 영역 league + 누적합 교차 정리
                                        T4  모델 좌표계로
                                        T5  마스크 갱신 (방식 C)
                                    ③ T6 리프값 (Goldschmidt)
                                    ④ 부스팅 라운드 반복 × T
모델 복호 / 또는 서버 추론  ←──────   Model, Theta, Leaf
```

**위협 모델**: 비대화형. 서버는 학습 전 과정에서 복호하지 않는다.
⚠️ 현재 `extract_branch` 가 복호된 `(j,k)` 를 받는다 → 비대화형 위반 (§6 F10).
**공개 파라미터**: `n, d, n_max, D, T, M(체인), subsample, mtry, λ, lr`.

**평문 기준 모델**: CatBoost (symmetric tree). 선행연구에 HE 상의 oblivious tree **학습**은 없다.
가장 가까운 것은 Masalha et al. PoPETs 2026 (비대화형 CKKS XGBoost, depth-wise).

## 1. 레이아웃

### 1-1. 학습 좌표계 ✅

```
slot[ (j·n_cat + b)·S + l ] = 1   iff   bin(x_lj) == b

  j ∈ [0,d)      feature
  b ∈ [0,n_cat)  bin,     n_cat = 2^⌈log2 n_max⌉
  l ∈ [0,S)      sample,  S = min(2^⌈log2 n⌉, M)
```

**두 단계 타일링** — 모든 n 을 수용.

| 경로 | 조건 | 예 |
|---|---|---|
| 기본 | `per_ct ≥ n_cat` (n_cat 배수로 내림) | cancer 379 → per_ct 64, 타일 4 |
| feature 분할 | `per_ct < n_cat` (2의 거듭제곱) | adult 22,793 → per_ct 1, 타일 48 |
| 샘플 청크 | `n_pad > M` | sepsis 77,239 → 청크 4, 타일 96 |

★ **subsample 은 최적화가 아니라 제약이다.** sepsis sub=0.1 → 타일 96 → 6 (16배).

**n_max 📐 미결** (`exp_nbins.py`):
n_max=8 은 n>5k 데이터셋에서 255 구간 대비 **AUC −0.009~−0.033**.
데이터 적응형 8 구간은 bank 에서만 이득. 고정 n_max 를 바꿀지는 아직 정하지 않았다.

### 1-2. 모델 좌표계 ✅

```
Model[ t·dp + f ] = 1  iff  f == j_t       dp = 2^⌈log2 d⌉
Theta[ t·dp ]     = (k_t + 1) / n_max
Leaf [ ℓ·dp ]     = 리프값                  ℓ ∈ [0, 2^D)
```
★ symmetric → 레벨당 분기 하나 → 모델 `D·dp` 슬롯 (비대칭은 `2^D·dp`).

## 2. 학습

### T0. subsample ⚠️ 인터페이스만

공개 난수 마스크 (pt 곱 1회). T1 비용이 n 에 직접 비례.

```
        n_tr <  10,000   →  1.0
10,000 ≤ n_tr <  50,000  →  0.5     (손실 −0.011)
50,000 ≤ n_tr < 200,000  →  0.25    (−0.011)
        n_tr ≥ 200,000   →  0.1     (−0.011)
```
★ d 에 크게 의존 (d=3 이면 110k 에서 0.1 이 −0.0004). 클라이언트가 평문 CV 로 결정.

### ① prefix 누적합 ✅ 오차 0

```
b 축 누적합 → slot[(j·n_cat+k)·S + l] = [ bin(x_lj) ≤ k ]
```
**비교 없이 회전/덧셈만.** `per_ct=1` 이면 회전 0회 (타일 간 carry = 덧셈).

### T1. 파티션별 통계 ✅ 오차 0

```
분류    L_q = Σ_l m_p·y_q·pre_{j,k}        선택 벡터 c 개
부스팅  G   = Σ_l m_p·g  ·pre_{j,k}        선택 벡터 2 개
        H   = Σ_l m_p    ·pre_{j,k}
```
타일당 **곱 1 + log₂(S) 회전**. 샘플 청크는 덧셈 합산.
★ 다중 클래스일수록 부스팅이 싸다 (soybean c=15 → 2).

### T2. 분할 점수 ✅ FHE 검증

```
분류    MGI   Σ_p [ L(L−N) + Σ_q L_q(N_q−L_q) ]        argmin
        ★ 인수분해로 ct·ct 곱  2c+2 → c+1

부스팅  gain  raw = Σ_p ( G'_L·H'_p − G'_p·H'_L )²     argmax
        ★ 항등식  ΣG²/H − G_p²/H_p = (G_L H_p − G_p H_L)²/(H_L H_R H_p)
          분자만 쓰면 나눗셈 소멸.  정확한 gain 대비 −0.016~+0.004
        ★ 분류 MGI 를 부스팅에 쓰면 −0.025~−0.127, 깊을수록 악화 → 금지
```

★ **점수 상한 버그 (현재 코드)**: `raw / (4·Σ_p H'^3)` 은 [0,1] 이 아니다.
  실측 최대 452, 레벨의 1~6% 에서 1 을 넘는다. 올바른 공개 상한은 **`4n`** (g 는 ‖g‖ 로 정규화, H' = H/n).
  → T3 의 log 입력은 `u = raw / (4n) ∈ [0,1]` 로 만든다.

**점수 레벨 · 정밀도 실측** ✅ (`test/test_score_level.py`, 실제 S9 호출 순서, 정규화 전 raw, n=128 d=8 D=4):

| 라운드 | 트리 레벨 | g | G_L | raw | **compact 점수** | 1등 크기 | 1등 상대오차 |
|---|---|---|---|---|---|---|---|
| 1 | 0 / 1 / 2 / 3 | 26 | 20/17/16/15 | 17/14/13/12 | **16 / 13 / 12 / 11** | 2^8.2 → 2^-1.9 | 1e-11 ~ 4e-10 |
| ≥2 | 0~3 | **10** | 7 | 4 | **3** | 2^7.6 → 2^-0.9 | 1e-6 ~ 5e-6 |

★ **정밀도는 충분하다.**  log 영역 argmax 가 요구하는 상대 정밀도는 ≈2⁻¹² (δ=2⁻¹⁰, t=32 → 상대 간격 2.2%).
  1등은 모든 레벨에서 평문과 일치, 1·2등 간격/오차 ≥ 10³.
★ **레벨이 병목이다.**  2 라운드부터 g 가 small-key refresh 로 레벨 10 에서 시작 → 점수까지 7 레벨
  (mask·g, pre·sel, `first` 마스크, broadcast, G·H, 제곱, compact) → compact 점수 레벨 **3**.
  league (입력 ≈ AB_DEPTH + 8) 도 log 단계도 못 돈다.
★ "작은 u 가 잡음에 묻힌다" 는 **작게 만든 뒤 refresh 할 때만** 생긴다. 공개 상수 곱은 상대 정밀도를 바꾸지 않는다.

### T3. argmax 📐 log 영역 league + 누적합 교차 정리

**현재 코드의 문제** (`normalize_score` + `argmax_league`, `ARGMAX_ALPHA=8`):

| 문제 | 실측 |
|---|---|
| 점수를 Goldschmidt 6회 절단으로 나눔 → 실효 축소 | 7~30% (t=5) |
| α=8 에서 1등·2등이 dead zone 안 (근접 동점) | 레벨의 **33~63%** |
| 그 결과 "빈" 지시자(아무것도 선택 안 됨)가 생김 | phoneme **−0.010** |
| `pick_alpha` 미정의 (train_core.py:1180) | 실행 불가 |

★ 예전 논거 "α(top) 만 필요" 는 **틀렸다**. 1등과 2등의 근접 동점이 흔하다.

**확정 설계**:

```
1) log 정규화      v_i = log2( u_i + 2^-t ) / t ,   u_i = raw_i / B (공개 상한),  t = 32
                   ★ 레벨 안 모든 후보가 같은 분모로 나뉜다 (데이터 의존이지만 공통)
                     → league 의 차분 v_i − v_j 에서 분모가 지워짐.  나눗셈·Goldschmidt 불필요
                   log 구현 📐 (평문 확인, FHE 미구현) — 아래 "log 범위 축소" 참고
2) league          ind_i = Π_{j≠i} sign01(v_i − v_j),   α = 10  (δ = 2^-10)
                   · sign 을 SIMD 로 1회,  ns² ≤ M  →  mtry 제한 (≤128 후보)
                   · ns² > M 이면 Masalha 계층형 argmax (d×d 블록 league, 라운드마다 d 제곱)
3) 교차 정리       c_i = Σ_{j≤i} ind_j,   w_i = σ(c_i − τ) − σ(c_{i−1} − τ)
                   τ ~ U(0.25, 0.75) 공개 난수,  σ = sign01 (α_post = 6)
                   · 깨끗한 multi-hot → c 가 정수 → 반격자 마진으로 '첫 번째' 를 정확히 선택
                     (DBSCAN 의 count − (min_pts − 0.5) 평행이동과 같은 원리, 점수 자체가 아니라 누적합에 적용)
                   · 흐린 지시자 → 질량 비율대로 하나를 랜덤 선택
                   · 질량 < τ → 선택 없음 → 그 레벨은 분할 없음 (무해)
```

**log 범위 축소** 📐 (평문, `experiments/exp_log_window.py` — 아직 `desilo/` 에 없음):

```
HEaaN-NB ApproxLog = (x·2^a 로 [1/√2,√2] 환원) + HermesLog.  환원 단계는 x 를 2^-b (b=0…t) 와 한 번에 병렬 비교.
  ✗ 그대로 못 쓴다: 절대값 비교라 경계 2^-28 을 가르려면 sign 정밀도 ~2^-30 필요
    (논문은 x≥2^-20 인 확률값 + HEaaN 고정밀 sign).  1등 u 는 2^-28 ~ 2^-4.6 (exp_log_range.py).
  ✓ 병렬 창 + 순차 단계:
      단계마다  p_b = sign01(2^-b − x)  (b = 1…W, W 개 경계를 SIMD 로 한 번)
                P = Σ_b p_b,   x ← x · E(P),  e ← e + P        E(P) ≈ 2^P  (체비셰프 deg 18, rel 4e-13)
      ★ x 와 e 를 같은 P 로 갱신 → sign 이 흐려도 (P 가 비정수여도) log 값이 정확히 유지된다
      마지막  log2 x ≈ ln-다항식(x ∈ [0.5, 1.1], deg 7~11) / ln2,   log2 u = 그것 − e
  창 W 는 sign α 가 정한다 (W ≈ α − 2).  α=10 → W=8,  α=16~18 (입력 레벨 16~20, §아래 DP) → W≈14~16.
```

| 덮을 범위 | 창 W | 단계 (sign 횟수) | log₂ 오차 (ln deg 7 / 11) |
|---|---|---|---|
| 32 bit (사전 스케일 없음) | 8 | 4 | 1.0e-6 / 1.0e-9 |
| 16 bit (레벨별 공개 사전 스케일 2^c_t) | 8 | 2 | 6.5e-7 / 5.4e-10 |

★ 단계 사이에 x 를 refresh 하면 안 된다 (작은 x 가 2⁻¹⁸ 잡음에 묻힘). 첫 단계들은 refresh 전에 끝내야 하고,
  x ≥ 2⁻⁹ 이 된 뒤에는 refresh 가능 (상대오차 2⁻⁹ 수준, log 영역 요구 2⁻¹² 대비 여유는 첫 단계 α 로 확보).

동점 처리: 근접 동점 후보 중 하나를 랜덤으로 골라도 AUC 손실 ≈ 0 (`exp_ties*.py`).
따라서 동점을 정확히 가릴 필요 없이 위 교차 정리로 하나만 남긴다.

**평문 FHE 시뮬레이션** (`exp_argmax_pipeline.py`, D=6 T=128, 5 데이터셋 × 3 seed):

| 변형 | AUC (ideal 대비) | 깨끗한 one-hot |
|---|---|---|
| 현재 (상한 정규화, α=8) | 최대 −0.010 | 낮음 (빈 지시자 다수) |

**sign 근사 — 성분 사이 sign_bootstrap DP** ✅ 단위 테스트 (`minimax_sign.py: build_composite_sb`, `test/test_dp_sign.py`):

```
성분 사이를 refresh 대신 sign_bootstrap = sin(πz/2) 로 잇는다
  · 출력이 항상 ≤ 1  →  다음 성분 정의역이 [cos(πτ/2), 1] (오른쪽 끝 고정, 스케일 폴딩 불필요)
  · 성분마다 오차 τ → (π²/8)τ² 로 공짜 축소
  · 목적함수  Σ (sign_bootstrap 시간 + 체비셰프 평가 시간)
  · 제약      각 성분 깊이 ≤ 시작 레벨 − 다음 부트 stage.  stage(3/4/5) 도 DP 가 고름
  · δ(입력 마진) 와 τ(출력 오차) 를 따로 받는다
  ★ 기존 minimax 논문의 α–차수 표를 그대로 쓰면 안 된다 (성분 사이 연산이 다름)
```

★ 정밀도 한계: refresh 후 절대 오차 2⁻¹⁸ (fresh 2⁻⁵⁰, 곱셈 후 2⁻³⁵).  refresh 를 거친 입력에 α>16 은 무의미.
   → 큰 α 비교는 refresh 전, 높은 레벨에서 sign_bootstrap 전용 계획으로.
★ DP 추정은 입력 레벨 26 계획에서 ~0.5 s 과소 (CHEB_MS 를 레벨 14 에서 쟀다 — 높은 레벨일수록 느림, §6 F21).

**improved Remez** ✅ (`remez_odd`, Lee et al. Eurocrypt'21 Alg.2·3 = Minimax sign 논문 §2.4 가 쓰는 알고리즘):

| deg, a | 구판 `minimax_odd` 1−τ (보고 / **참**) | `remez_odd` 1−τ (보고 = 참) |
|---|---|---|
| 31, 2⁻²⁴ | 3.1e-6 / **−3.7e-5** | 3.11e-6 |
| 63, 2⁻²⁴ | 6.3e-6 / **−2.2e-4** | 6.32e-6 |
| 127, 2⁻¹⁷ | 1.6e-3 / **−4.6e-2** | 1.63e-3 |
| 127, 2⁻³⁰ | 발산 (1.5e16) | 1.69e-7 |

★ 구판은 작은 a 에서 극점을 놓쳐 **참 1−τ 가 음수** — a 근처에서 다항식이 0 아래로 내려가 **부호 반전**.
  이전 "α≥24 해 없음" · "deg 63 오차 과소평가" 가 모두 이 버그였다.
★ 고친 것: 극점 3분 탐색 정밀화 (Alg.2) · 교대 + 최대 절대합 선택 (Alg.3) · 초기점 a+(1−a)·sin(πs/2)
  (체비셰프 노드는 홀수 기저에서 cond 1e11~1e17, sin 배치는 ≈10).  deg 7~127 · a=2⁻⁴~2⁻³⁰ 에서 보고 = 참.
  남은 실패: deg 127 · a=2⁻⁴ 하나 (DP 가 후보에서 제외).
★ `build_composite` (구 경로, `argmax_league` 가 아직 사용) 는 여전히 `minimax_odd` — α=8 (a=2⁻⁸) 은 문제 없음.

✅ 가정 검증: sign_bootstrap 은 z ∈ [−1.98, 1.98] 전체에서 sin(πz/2) 를 따른다
   (오차 ≤ 8.1e-7, stage 3/4/5 무관, 작은 z 에서 기울기 1.5705 ≈ π/2).
✅ cheb_dep(d) = ⌈log2(d+1)⌉ + 1 이 deg 3~127 실측과 일치 (127 은 test_dp_sign2 에서 확인).
★ 기존 경로는 오차가 훨씬 작다 (7.7e-7). DP 는 목표 τ 까지만 맞추는 대신 시간을 반으로 줄인다.
   argmax 에 필요한 τ 는 아래 시뮬레이션으로 정했다 → **τ≈2⁻⁹ (dp8, 3.82 s) 로 충분**.

교차 정리 sign 도 DP δ=2⁻⁵ τ≤2⁻⁶ [3,7] 2.65 s, 추론 sign DP [31], D=6 T=128, 5 데이터셋 × 3 seed):

★ τ 가 ns−1 개 인자 곱에서 누적돼 승자 값이 0.94 까지 내려가지만, 교차 정리가 흡수한다 → AUC 영향 없음.

### T5. 마스크 갱신 — 방식 C ✅ 오차 0

```
m_left  = m_p ⊙ b            곱 1회
m_right = m_p − m_left       ★ 뺄셈
L[2p+1] = L[p] − L[2p]       ★ 대수적 항등식, 오차 0

```

### T6. 리프값 🟡 오차 1e-16

```
leaf[ℓ] = + lr · G[ℓ] / (H[ℓ] + λ)        λ = n/2^D (공개)
```
★ **부호 규약**: G 는 **잔차 합**(y−F). gradient(F−y) 를 넣으면 발산.
★ λ 가 분모 하한을 만들어 `H+λ` 범위를 `(2^D+1):1` 로 압축 → Goldschmidt `D+5` 회.
★ **log 로 대체하지 않는다.** T3 와 달리 리프마다 분모가 달라서 지워지지 않고,
  결과값 자체가 필요하다 (exp 복원 + G 부호 처리 필요). Goldschmidt 유지.

| | 반복 | ct·ct 곱 | 깊이 | 상대오차 |
|---|---|---|---|---|
| D=4 | 9 | 16 | 12 | 3e-14 |
| D=6 | 11 | 20 | 14 | 1e-14 |
| D=10 | 15 | 28 | 18 | 9e-15 |

**기각된 대안** (전부 깊이에서 실패):

| 방법 | 나눗셈 | D=4 손실 | 이유 |
|---|---|---|---|
| 기대 크기 `G·2^D/n` | 없음 | −0.030 | 리프 크기 편차 무시 |
| sign + 고정 스케일 | 없음 | −0.046 | 잔차 감소를 못 따라감 |
| sign + 전역 스케일 | 없음 | −0.040 | 리프별 편차 못 담음 |
| Richardson `v+=η(G−Hv)` | 없음 | 발산 | 조건수 2^D → 반복 O(2^D) |

★ Richardson 이 **soft tree 가 400 에폭을 돌려야 했던 이유**와 같다 (같은 1차 반복).

## 3. 추론 ✅ 실제 FHE 20/20

```
I1  입력을 D 블록에 복제                       회전 log₂D
I2  feature 선택 ⟨Model, x⟩                    ct·ct 1 + 블록합
I3  비교 sign(Sel − Theta)                     ★ 트리 전체에 1회
I4  b_t 를 전 리프에 복제 후 β 와 XOR           ★ stride 확장 불필요
```

★ **마진이 binning 으로 보장**된다 — `θ=(k+1)/n_max`, `x=(b+0.5)/n_max`
  → `|x−θ| ≥ 1/(2·n_max)` → 추론 sign α=4~8.
  **argmax 와 성격이 완전히 다르다** (그쪽은 보장 없음).
★ 추론 sign 은 이미 성분 1개 ([27], 1.41 s) — sign_bootstrap DP 이득 없음 ([31] 1.42 s).
★ HEaaN-ID3 (CMC 2025) 는 리프→루트 bottom-up 접기로 추론한다 (레벨마다 one-hot 입력으로 자식 하나 선택, ApproxSign 0회).
  다지 범주형 ID3 와 빈 노드(c_a=0) 처리에 맞는 구조다. 우리 symmetric 구조에선 접기 깊이가 D 라
  현 I4 (리프별 D 비트 곱, 깊이 ≈ log₂D) 보다 깊어 이득이 없다.

```
       비대칭 노드평가  symmetric   배율      모델 슬롯
D=6         63             6      10.5x     2,016 → 192
D=8        255             8      31.9x     8,160 → 256
D=10     1,023            10     102.3x    32,736 → 320
```
★ 이 배율은 **추론과 학습의 argmax·T4 에만** 적용된다. 학습의 T1/T2/T5/T6 은 여전히 O(2^D).

### symmetric 이 정확도에서 잃는 것 📐 (`exp_sym_vs_asym.py`)

| 비교 | 결과 |
|---|---|
| 같은 AUC 에 필요한 트리 수 (sym / asym) | 대개 1~2.5배, 최악 약 4배 (electricity) — (2^D−1)/D 보다 작음 |
| 같은 FHE 비용 (argmax 만 셈) | **sym 이 14/16 승** |

→ (D, T) 최적화 곡선은 아직 안 그렸다 (§6 F15).

## 7. 정리된 논거

```
① 노드 표현 (onehot_j, θ)   모델·추론이 depth 에 대해 지수 → 선형

⑥ log 영역 league           공통 분모가 차분에서 소멸 → argmax 정규화에 나눗셈 0
⑦ 누적합 교차 정리          동점·흐림을 하나로.  반격자 마진.  99~100% one-hot, ±0.001 AUC

                            → argmax sign 2.6배 빠름 (9.86 → 3.82 s), refresh 없이 α=24 (4.9 s), FHE 실측
```
